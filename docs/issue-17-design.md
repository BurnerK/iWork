# #17 文字文档正式保存合同

首版正式输出选择 UTF-8 Markdown（`.md`），正文上限 256 KiB，标题 1–120 字符且不含路径或控制字符。页面以只读、保留换行的文本预览，不执行 HTML、脚本、外链或 Markdown 中的代码；下载返回原始 Markdown 内容与附件文件名。不引入富文本编辑器、DOCX/PDF、表格或演示文稿。

提交任务时明确选择文字回复或生成 Markdown 文档。省略输出模式时默认文字回复。文档任务仅在正式版本登记成功后完成。模型只获准当前任务业务工具：读取授权资料、准备文字文档，不提供通用文件或 shell 工具。未调用文档生成工具、只有聊天回复时不能把文档任务报告为成果成功。

模型生成工具先把有界正文写入独立任务工作区，再登记准备记录；每个任务只准备一个文档，重复相同内容返回同一记录，不允许重试产生多个正式版本。文件采用临时写入、force、同目录原子移动；路径完全来自系统 UUID，不使用模型提供路径。资料原文不变。

Harness 返回后由业务层核对准备记录及完整文件，准备不可变正式文件，再在与取消共用的任务行锁事务内登记独立成果 ID、版本 ID、文件索引、回复和任务完成态。SDK 完成不发布成果；取消已成立时不登记版本；完成已提交后取消不追溯删除。首次版本为 1，基于旧版本修改由 #18 扩展。

MySQL 与文件系统没有统一事务。正式完整文件先落盘、数据库索引后提交，下载按长度与 SHA-256 校验。保存失败不登记不完整版本；DB 提交结果不明时保留完整孤立文件，避免删除可能已登记成果。只能在服务停止并核对数据库索引后清理无引用文件。已确认的临时文件可清理；原始资料和正式文件不属于任务工作区清理范围。

预览/下载/列表均按当前调用者校验所有权；成果与版本、任务各自独立身份。会话页面展示正式成果版本与下载入口，刷新和服务重启后从持久记录找回。正式版本 immutable，不覆盖已有正文。

验收以真实身份/MySQL/文件/受限解析容器/Harness、外部模型传输替身为主：资料→理解→生成工具→提交→预览下载全文核对；重复发布、取消先成立、提交先成立、文件保存失败、越权和重启可读。#19 再扩展多服务迟到竞争矩阵，#25 再验生产协调备份恢复。
