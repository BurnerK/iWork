# ADR-0001: 主应用管理任务，沙箱隔离文件处理

**日期**: 2026-11-12

**状态**: 已接受

**决策者**: Eren <burnerk@foxmail.com>

## 背景

首版服务少量内部用户，一次任务涉及身份、模型额度和成果发布。上传资料需要在受限环境中解析。原型显示，取消 SDK 调用或让主应用退出，都不能保证处理容器随之停止。

## 决策

身份、任务、成果、计量和 AgentScope 执行循环放在同一 Java 后端。主应用只向独立沙箱管理服务提交获准资料和固定操作，由管理服务创建和回收容器；独立看门狗按实例标签和 Docker 创建时间回收到期容器。2026-11-16 确定执行循环采用 [HarnessAgent](0004-harness-runtime-and-context.md)。

## 考虑的备选方案

### 备选方案 1: 独立部署智能体运行服务

可单独部署执行循环，但任务状态、授权、额度和成果提交需要跨进程协调。首版选择在主进程内按模块分工。

### 备选方案 2: 主应用通过 SDK 直连 Docker

可以复用 SDK 的容器管理能力，但普通 Docker socket 给主应用过大的宿主权限，容器内计时器也无法覆盖不可信处理程序。

## 影响

### 积极影响

业务取消和成果发布可以在主应用内协调，迟到结果无法发布。处理容器只接触本次获准的资料。

### 消极影响

升级或崩溃会中断正在执行的任务；已保存内容可找回，中断任务需要用户重新发起。

### 风险

管理服务和看门狗均持有容器管理权限。期限依赖 Docker、宿主和看门狗可用；清理结果未知时保留状态并重试。2026-11-12 接受了原型结果及这些限制。[第三阶段验证](../../prototypes/sandbox-validation/ROUND3.md)
