# 首版主应用与执行边界

当前状态：2026-11-12 用户已接受第三阶段验证结果和限制，#8 与 #6 均已收口。下文按阶段保留决策历史；最终方案见末尾独立执行看门狗补充与收口记录，早期“待验证/待审阅”不代表当前状态。

2026-11-12 确认：首版采用模块化单体。身份与资源、会话与任务、成果与文件、模型与用量，以及 AgentScope 执行循环位于同一个 Java 后端进程，通过模块接口划分责任。首版面向少量内部用户，优先降低部署与运行协调成本，暂不将智能体运行模块拆成独立服务；接受主后端升级或崩溃中断正在执行的任务。

用户上传资料的解析与文档转换在独立受限的执行环境中进行，仅获得本次任务所需文件，不获得主数据库及模型凭据，并限制资源与访问范围。这增加执行环境管理成本，但有助于限制解析器故障或恶意输入对主应用的影响。整体基线确认后优先采用 Docker 沙箱，具体接入方式仍待验证，不能将任务目录隔离视为已完成 OS 级隔离。

首版主要技术栈方向为 Java 21、Spring Boot、AgentScope Java，以及 Vue 3、TypeScript。具体依赖版本与兼容性仍需核查；原型使用 AgentScope Java 2.0.4，不等于已冻结生产依赖版本。

文件处理隔离优先复用 AgentScope Java 2.0.4 已提供的 [Docker 沙箱接入能力](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/harness/filesystem.md)，复用其容器生命周期管理，显式将平台预置的解析与转换程序放入容器执行。模型仅获得受控业务工具，不开放通用 shell；自定义 Java 工具不会因为配置沙箱就自动迁入容器。资源、网络、文件挂载及容器管理权限仍需明确配置并验证，不能将 SDK 默认配置视为生产隔离验收。该优先方向已随整体架构基线确认，尚未完成集成验证或冻结最终接入方式。

以上决定沿用 [运行职责决议 #4](https://github.com/BurnerK/iWork/issues/4#issuecomment-6816656401) 和 [原型收口决议 #7](https://github.com/BurnerK/iWork/issues/7#issuecomment-6821251509)：iWork 持有业务状态，浏览器断连不结束任务；进程重启保留已保存内容，将未完成任务标记中断且不自动续跑；取消后拒绝迟到的正式成果发布。[整体架构基线](../first-release-architecture.md) 已共同确认；沙箱接入仍待验证，[模块与部署议题 #6](https://github.com/BurnerK/iWork/issues/6) 尚未收口。

2026-11-12 验证补充（非新决议）：[#8 探针](../../prototypes/sandbox-validation/README.md) 已取得受控容器处理、隔离与生命周期正反向证据。普通 Docker socket 直连扩大主应用权限；SDK stop/超时/调用取消与主应用崩溃不保证处理进程停止。显式 shutdown 和启动回收可补充生命周期，但管理权限及是否增加受限管理服务仍待用户讨论。原决议保持，不能据此将 #6 或生产隔离标记为验收通过。

## 2026-11-12 沙箱接入修订（用户已确认）

用户选择增加受限沙箱管理服务，取代主应用直连普通 Docker socket 的验证路径。主应用保持模块化单体，智能体循环与业务权威仍在主应用；新增服务只接收获准资料和固定处理操作，负责受限任务容器的创建、取消、超时与回收，不获得主数据库或模型凭据。接口拒绝任意命令、镜像、宿主挂载及 Docker API 转发，并实施服务与任务授权。

该决定接受增加组件与管理协议的成本，降低主应用直接触达整个 Docker 引擎的权限。管理服务仍为高权限信任边界。第二阶段原型已验证调用、授权、取消/超时与进程崩溃恢复；固定镜像内计时器并不抵御恶意处理程序，生产强制期限及 Linux 实机等仍需另验。结果见 [#8 探针](../../prototypes/sandbox-validation/README.md)，最终证据待审阅，不代表生产验收。

## 2026-11-12 强制期限补充（用户要求，最小方案已验证）

用户明确要求期限在处理容器外，并覆盖管理服务失效。采用独立执行看门狗，依据 Docker 创建时间与实例标签实施回收；移除同 UID 的容器内计时器。主应用仍持有业务终态，业务取消禁止发布；进程终止与清理确认独立记录，未知时保留待重试而不报告停止。三组补证及独立期限见[第三阶段报告](../../prototypes/sandbox-validation/ROUND3.md)。看门狗与 Docker/宿主仍可用是停止上限的前提，不把本机样本时间视为全故障场景保证。

## 2026-11-12 最终验收与收口

2026-11-12 用户已接受最终验证结果与限制，[#8 接入验证](https://github.com/BurnerK/iWork/issues/8#issuecomment-6826203433)与[#6 架构决策](https://github.com/BurnerK/iWork/issues/6#issuecomment-6826209370)均已完成收口。生产 Linux、正式身份、真实解析器、数据库成果事务及恢复等仍待实施验收；停止上限依赖看门狗、Docker、宿主调度与时钟可用，探针时间不是生产 SLA。前述阶段性待审阅状态已结束；最终边界以独立执行看门狗补充及收口决议为准。
