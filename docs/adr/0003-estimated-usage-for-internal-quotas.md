# ADR-0003: 按模型调用估算缺失用量并释放预占

**日期**: 2026-11-12

**状态**: 已接受

**决策者**: Eren <burnerk@foxmail.com>

## 背景

同一任务可以多次调用模型，每次调用的供应商用量回报可能不同。调用结束后仍缺少完整回报时，系统既要记录已发生的消耗，也要让用户继续使用剩余额度。

## 决策

每次调用单独核算：有有效回报时按供应商数据计量，缺少完整回报时按可观察的输入和输出估算，记录估算来源及供应商用量待核实状态。执行收尾后释放预占。2026-11-16 确认主推理、压缩、溢出恢复及实际重试均受同一用户授权、预算、取消和尝试上限约束。

## 考虑的备选方案

### 备选方案 1: 核实用量前持续保留预占

可以延后核算未知费用，但供应商可能一直不补报。长期冻结预占会让内部用户无法使用余额，因此选择在收尾时释放。

## 影响

### 积极影响

单次缺报有明确记录，任务中其他调用的有效回报仍可独立核算。

### 消极影响

内部估算可能与供应商费用存在差额。

### 风险

缺报若被记为零会漏计费用。账本须保留来源和待核实状态；预占算法、无法可靠估算时的处理和差额调整细则留给计量设计。任务终态后不再发起后台记忆维护调用。[原型收口决议](https://github.com/BurnerK/iWork/issues/7#issuecomment-6821251509)
