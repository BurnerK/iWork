# ADR-0002: 使用单机 Docker Compose 部署

**日期**: 2026-11-12

**状态**: 已接受

**决策者**: Eren <burnerk@foxmail.com>

## 背景

部署者需要在一台 Linux 主机上运行首版，并能在维护窗口内升级和恢复。业务记录和文件必须能一起恢复。2026-11-16 又明确要求正常重建服务后保留登录态。

## 决策

前端随 Java 应用交付，Compose 在同一主机运行主应用、MySQL、沙箱管理服务和独立看门狗。MySQL 保存业务数据，持久文件目录保存原文和成果，两者协调备份。2026-11-16 增加 Redis，以 AOF 命名卷保存 Spring Session；Harness 的上下文快照和摘要随业务历史存入 MySQL。

## 考虑的备选方案

### 备选方案 1: 使用 Kubernetes 编排

可支持更复杂的多机部署，但首版面向单机和少量用户，可以接受维护停机，引入集群会增加部署和运维成本。

### 备选方案 2: 只部署 MySQL，省去 Redis

这是 11 月 12 日的初始方案，服务更少。为在应用重建后保留登录态，11 月 16 日批准增加专用于 Spring Session 的 Redis。

## 影响

### 积极影响

一个 Compose 项目可以管理整套服务。主应用通过内部网络请求沙箱，只有管理服务和无网络的看门狗挂载 Docker socket。

### 消极影响

维护期间需要停写。恢复时须使用相互匹配的数据库备份、文件目录和应用版本。

### 风险

单台宿主故障影响整个实例。Redis 不可用时认证请求返回 503；登录态丢失需重新登录。readiness 同时检查 MySQL、Redis 和文件目录。[部署与恢复](../DEPLOYMENT.md)
