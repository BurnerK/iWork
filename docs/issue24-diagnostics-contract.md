# #24 任务运行诊断

用户从自己的任务打开诊断；管理员从运行诊断页按任务 ID 或最近任务定位。普通入口始终校验 owner，管理员跨用户查看仅通过另行校验 ADMIN 的受限入口，不能由此读取会话正文、原文或成果。

`GET /api/tasks/{id}/diagnostics` 与 `GET /api/admin/tasks/{id}/diagnostics` 使用同一显式字段投影，返回 task/calls/parses/versions。`GET /api/admin/tasks?page=0` 每页 20 项，不含标题、文件名、智能体/项目指令、模型地址、凭据引用、供应商返回标识、任务令牌或私有内容。金额保持十进制字符串，与原逐调用接口一致。

时间线以任务创建/状态更新时间、模型开始/发送/用量更新/本地收尾时间、资料处理创建/观察/清理尝试/首次确认时间、成果正式发布时间关联。任务 ID 关联调用与处理作业；处理作业 ID 同时对应沙箱注册记录及 Docker `iwork.job` 标签。管理员可据此在受控运维环境定位容器，无需把 Docker 管理能力暴露给 Web。查询是当前已持久化观察，不声称跨子记录原子快照或每次历史转换的完整事件日志。

业务取消、本地执行结束、供应商响应完成、供应商用量是否完整、处理容器清理分别显示。已发送但未观察完成的供应商执行为 UNKNOWN；响应完成但缺少 usage 仍待核实。资料处理 RUNNING 与清理 UNKNOWN 不等于已请求停止；业务终态后的 UNKNOWN 明确为停止未知/清理待重试。首次清理确认时间不是当前时间的存活探针。

任务新增上下文构建/恢复/快照不一致状态、摘要未需要/运行中/采用/回退/失败观察；不记录摘要正文。MAIN、SUMMARY、OVERFLOW 沿用原调用账本。取消或重启时若摘要仍标运行中，页面明确该阶段结果未确认，不宣称已完成摘要。

模型失败只记录固定代码，SDK/响应异常正文不写入诊断。关闭 AgentScope 与 Reactor publisher 默认异常日志，防止其中带有模型响应或工具参数；应用故障仍通过受限代码及数据库记录定位。HTTP 错误不带栈、消息或配置。不要在共享环境重新开启 SDK DEBUG/TRACE。容器轮转限制沿用 3×10MB。

记录与业务任务保留在同一 MySQL 中，纳入协调备份；本票不自动清理历史、不建立队列或独立观测平台。V13 以前的上下文观察标为 NOT_OBSERVED，旧清理记录不伪造尝试次数和确认时间。日志与备份仍需部署者限定访问。
