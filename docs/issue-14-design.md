# #14 Harness 执行与计量契约

正式入口采用 AgentScope HarnessAgent / OpenAI 兼容适配器 2.0.4。第一步仅文字推理，无业务工具；显式关闭文件/Shell/Web、动态 Skill/MCP、子智能体、Plan Mode、长期记忆、独立日志、默认目录持久化、压缩和大结果卸载。#16/#17 后续添加固定获准业务工具，#27 添加业务 MySQL 上下文与自动压缩。

统一调用边界覆盖 MAIN、SUMMARY、OVERFLOW。每次实际订阅都新建调用记录，重新核验实际调用者、任务状态、模型权限和预算；不能通过辅助用途绕过。每任务最多 4 次实际尝试，不自动重试网络错误，单调用总期限 120 秒，输出最多 2048 tokens。SDK 和模型适配器内部重试关闭。

输入估算采用序列化输入的 UTF-8 字节数加 512 个协议余量 tokens，最多 131072；这是保守内部估算，不声称等于供应商 tokenizer。预占以此输入估算与 2048 输出上限乘价格，按百万 token 单价计算，金额向上取 6 位小数。无法取得有界输入时在发送前拒绝。并发调用在个人预算行锁下扣可用额度；价格、币种在调用时快照。

供应商流中原始 usage 的非负累计 prompt/completion token 分别保留，不将适配器推算值冒充供应商回报；重复累计回报不相加。缺失输入用输入估算，缺失输出用已经观察到的 UTF-8 输出字节数；完全未观察到输出时用输出上限保守估算；重启使用已持久化观察，无法观察的部分继续待核实。已有的单边有效回报仍保留。收到供应商完成信号且两边完整回报才标记 PROVIDER；完成前的累计回报保留为已知下限并与观察估算取较大值，标记 PARTIAL_ESTIMATE，否则展示用量待核实及估算来源。成功、失败、取消、重启都完成内部核算并释放预占，不永久冻结、不将未知自动置零。

取消作用于当前实际订阅，不为了等 usage 继续生成。内部核算不等于供应商已经停止或结清。已记录可靠回报优先；迟到可靠回报可替换缺失部分并产生带前值/后值/依据/时间的差额记录，更新 spent 但不重复释放预占。实际费用超过预占时记录真实差额，后续可用预算归零，不隐藏超支。凭据与提示词不进入用量记录或公开错误。


`GET /api/tasks/{id}/calls` 只返回调用者自己的任务调用，包含用途、供应商回报、观察估算、价格对应的内部金额、状态、时间、标识及调整记录。页面通过“查看用量”显示，未知供应商用量不会显示为 0。

用量观察持久化采用累计字节数与累计供应商 token 的单调最大值，数据库异常时只重试这些幂等写入，不重发模型请求。数据库恢复后再完成核算；若进程在无法写入时被强制终止，恢复只能依据已持久化观察，未持久化部分仍待核实。并发收尾使用当前行锁读，防止 MySQL RR 快照导致重复释放。

SDK 源码核查：`maxRetries(1)` 在 core 内映射为 maxAttempts=1，而非额外重试一次；零值被 builder 拒绝。Harness 关闭子智能体后仍会注册 `wait_async_results`，正式入口在构建后移除并断言空工具集合；供应商边界也拒绝意外 schema。没有调用默认用户目录的状态存储。
