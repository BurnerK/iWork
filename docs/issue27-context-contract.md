# #27 上下文恢复与压缩契约

本地实现与确定性验收见 [验证记录](validation/issue27-context.md)；未声明真实模型质量或目标 Linux 验收。

模型管理增加获准上下文窗口，8192–131072 Token；更大模型在首版只使用 131072。既有模型迁移后窗口为空，必须由管理员按供应商规格配置才能执行。确定性替身的窗口是测试参数，不能用于推断真实模型能力。

每次实际调用仍经 GovernedModel、当前授权和逐调用额度账本。输入按序列化 UTF-8 字节保守估算，另留 512 开销与 2048 输出；超过当前窗口即拒绝发送。任务全部用途合计最多四次尝试，单次 120 秒。摘要也采用 2048 输出上限，另限制正文 8192 UTF-8 字节。

显式新任务读取当前用户/会话中 COMPLETED 任务的业务消息。消息完整保留在 messages；失败、取消和中断任务的消息仍能查询，但不进入模型恢复上下文。每个成功任务对应一个会前上下文快照，包含处理本次请求前的背景、此前业务消息水位与 SHA-256 校验，以及摘要；后续请求追加水位之后的成功业务消息。只复制文本背景，当前权限、工具、运行迭代和待执行工具均重新初始化。不会启动历史任务。

conversation_contexts 关联来源任务、实际 owner、conversation。保存失败导致本次任务失败；只有来源任务最终 COMPLETED 的快照可以被读取。因此取消、文档发布失败、进程中断以及完成事务回滚均不会激活候选快照。旧快照和完整历史不被覆盖。摘要与快照保存在 MySQL，工作目录不承担恢复存储。

恢复时验证所属关系、业务水位及历史前缀摘要、快照内容摘要、序列化用户/会话、纯文本消息类型。失配时从完整成功业务历史重建；无法在有界内存中重建则明确失败。历史校验使用 JDBC 流式读取，重建/追加部分最多 2 MiB，不把无限历史装入堆。

每次新任务使用窗口减 4096 作为背景及当前输入预算，达到该预算的一半尝试一次官方 ConversationCompactor，保留最近两条业务消息，之前的摘要一同参与再摘要。禁用记忆写入、独立日志卸载、参数截断和工具结果剪枝。Harness 推理中的通用文件卸载与自动重放恢复仍关闭；本次工具结果超过当前调用窗口时明确失败，不自动重放工具。

2.0.4 官方摘要器会把异常/空返回变成占位文字，因此在统一模型入口外记录实际摘要流成功完成、有效文本与长度；只有满足这些条件才接受压缩结果。否则原背景预算内可继续，超过预算则失败。压缩后仍超预算也失败。错误占位不进入可用快照。真实摘要内容正确性由 #26 验收。

参考锁定构件及[官方压缩文档](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/harness/compaction.md)。
