# iWork Web 首版实施规格

整理日期：2026-11-16（Asia/Shanghai）。状态：产品与架构沿用已确认决议，用户已确认 Testing Decisions 中的测试边界，并授权发布本规格。本文作为后续拆分实施票的依据，不是实现完成或上线验收报告。

## Problem Statement

产品发起者与少量内部同事需要在自己部署的 AI 应用中，使用自己的资料生成文字文档，并能隔天找回、继续修改。仅有聊天回复或一次性生成文件不足以支撑持续工作：用户需要清楚的资源归属、可找回的成果版本、可观察和取消的后台任务，以及有效的模型权限与个人额度限制。

当前仓库已有架构、领域决议与运行/沙箱探针，尚未形成正式 Web 业务应用。探针证明部分集成和故障行为可行，正式身份、数据库事务、真实文件解析和目标 Linux 部署仍需实施与验收。

## Solution

交付单部署实例、小范围内部试用的 Web 应用，完成以下闭环：

管理员配置账号、模型、使用权限与个人额度 → 用户登录 → 新建个人会话或项目空间 → 直接提供资料，使用模型或配置式智能体处理 → 生成文字文档成果 → 预览、下载、保存 → 隔天找回并在会话中继续修改，形成独立版本。

后台任务不依赖浏览器保持连接。用户能够查看进度与结果、取消任务；失败、取消或重启不破坏已保存的成果。文件解析与转换通过受限沙箱管理服务执行，独立执行看门狗在处理容器外实施期限。

开放试用以核心闭环及上线门槛通过为条件，不承诺固定日期、多机高可用、无限并发或供应商最终费用与内部估算完全一致。

## User Stories

### 管理员与试用准入

1. 作为部署者，我希望在单台 Linux 服务器上部署一个 iWork 实例，以便本人和少量内部同事使用。
2. 作为管理员，我希望配置首批试用者所需的账号与登录入口，以便授权用户能够进入应用。
3. 作为管理员，我希望统一配置上游模型及其访问凭据，以便用户无需持有供应商密钥也能使用模型。
4. 作为管理员，我希望为用户设置可用模型，以便模型使用符合实例的授权规则。
5. 作为管理员，我希望按实例配置的币种和计价规则设置个人额度，以便控制内部模型预算。
6. 作为管理员，我希望查看与用户、任务和模型调用关联的用量及异常记录，以便定位费用和执行问题，而不因管理角色自动获得私人内容读取权。

### 个人工作与资料

7. 作为试用用户，我希望登录后找回自己的会话、项目空间和成果，以便持续开展工作。
8. 作为用户，我希望创建独立个人会话，以便不创建项目也能开始一次资料处理工作。
9. 作为用户，我希望创建个人项目空间，组织会话、项目指令、参考资料和成果引用，以便持续处理同一项目的工作。
10. 作为用户，我希望将自己的会话移入或移出项目空间，以便调整组织方式而不改变资源所有者。
11. 作为用户，我希望删除项目空间时保留其关联会话和成果，以便组织调整不会误删独立内容。
12. 作为用户，我希望直接提供本次工作所需的资料，以便不依赖知识库或外部业务系统也能完成任务。
13. 作为用户，我希望只有获准的资料和成果版本被本次任务使用，以便私人内容不会被其他用户或任务读取。
14. 作为用户，我希望从获授权的模型中选择本次工作所需模型，以便完成内容理解和生成。
15. 作为用户，我希望配置智能体的指令、模型等首版配置，并使用平台内置资料处理和成果生成能力，以便复用工作要求。

### 后台任务与可见状态

16. 作为用户，我希望提交后能识别并查询同一次任务，以便知道请求是否已受理以及处理进展。
17. 作为用户，我希望重复提交同一请求不会触发重复执行，以便连接异常或重试不会重复生成成果或消耗额度。
18. 作为用户，我希望同一会话已有任务时得到明确反馈，以便等待其结束或取消后再发起下一次工作。
19. 作为用户，我希望不同会话能在实例容量允许时分别执行任务，以便工作互不混淆。
20. 作为用户，我希望关闭网页后后台仍继续执行，以便不必一直保持页面打开。
21. 作为用户，我希望重新打开页面时看到原任务的状态与结果，以便恢复观察而不重新执行。
22. 作为用户，我希望清楚区分运行、完成、失败、取消和重启中断，以便判断下一步操作。
23. 作为用户，我希望取消任务后阻止其后续正式成果发布，并保留已有成果，以便停止不再需要的工作。
24. 作为用户，我希望处理进程尚未确认停止时得到如实说明，以便不会把业务取消误认为所有执行和费用均已停止。
25. 作为用户，我希望任务失败时保留已保存内容并提供可定位的失败信息，以便决定是否重新发起工作。
26. 作为用户，我希望服务重启后仍能找回已保存内容，未完成任务明确显示中断，以便知道哪些工作需要重新发起。

### 正式成果与版本

27. 作为用户，我希望任务生成可预览的文字文档成果，以便检查实际内容而不只看到完成提示。
28. 作为用户，我希望下载已保存的文字文档版本，以便在应用之外使用。
29. 作为用户，我希望隔天仍能找回已保存成果和版本，以便继续工作。
30. 作为用户，我希望在会话中基于已有成果提出修改要求并生成独立版本，以便保留先前内容。
31. 作为用户，我希望自己的成果能被多个会话或项目引用，以便复用成果而不依赖某段会话的生命周期。
32. 作为用户，我希望保存失败、任务取消或迟到结果都不会覆盖旧版本，以便已有成果保持完整。
33. 作为用户，我希望执行工作文件被清理时原始资料和正式成果仍保留，以便运行维护不影响个人内容。

### 权限、额度与故障运营

34. 作为用户，我希望其他用户不能通过猜测标识查看、修改、下载、取消或引用我的私有资源，以便保持个人内容隔离。
35. 作为用户，我希望模型权限和额度不足时得到明确反馈，以便理解本次工作不能继续的原因。
36. 作为用户，我希望成功、失败和取消的任务都保留已经发生的模型用量，以便了解真实可观察的消耗。
37. 作为用户，我希望缺少供应商最终回报时看到估算来源与“用量待核实”，以便不会把未知误认为零消耗或已结清。
38. 作为用户，我希望执行收尾后释放额度预占，以便不会因供应商用量未知而长期无法使用剩余额度。
39. 作为运维人员，我希望任务容器能够在取消、超时和管理服务故障后按既定边界终止与回收，以便控制遗留处理资源。
40. 作为运维人员，我希望清理失败留下持久记录、阻止新增处理任务并在恢复后重试，以便故障不被掩盖或持续累积。
41. 作为运维人员，我希望看门狗失效时停止接纳新的处理任务，以便在缺乏期限监督时不继续扩大执行风险。
42. 作为部署者，我希望能够升级应用并协调备份、恢复数据库和文件，以便保留用户已保存的内容。
43. 作为试用负责人，我希望本人和同事能用真实资料独立完成生成、隔天找回和继续修改，以便以实际工作结果判断能否开放试用。

## Implementation Decisions

### 1. 范围、技术栈与职责

- 首版为单实例内部试用。使用 Java 21、Spring Boot、AgentScope Java 的模块化单体；前端使用 Vue 3、TypeScript，构建后随应用交付。
- SDK 探针基线为 AgentScope Java 2.0.4，不据此宣称全部生产依赖版本及兼容性已冻结。正式版本组合在实现时核查并固定。
- 主应用的五个逻辑模块及其对外能力如下，不要求它们之间通过 HTTP 通信或分别部署。

| 模块 | 责任及稳定能力 |
| --- | --- |
| 身份与资源 | 识别调用者、管理登录与资源归属、校验每次资源访问及模型使用权限 |
| 会话与任务 | 保存消息和任务，提交/查询/取消，提供状态与事件，保证幂等和同会话互斥 |
| 智能体运行 | 应用本次获准的指令、模型与工具配置，托管 SDK 执行、取消和调用观测；不自行决定业务终态 |
| 成果与文件 | 管理原始资料、工作区、成果与版本；提供获准输入、准备内容、条件提交、预览和下载 |
| 模型与用量 | 配置模型、授权调用、预占和核算额度，逐调用保存供应商回报或估算，收尾释放预占 |

### 2. 领域与授权

- 会话、任务执行、项目空间、执行工作区、成果及成果版本分别具有各自身份与生命周期。项目空间组织和引用资源，不接管其所有权；删除项目不级联删除关联会话或成果。
- 当前直接使用入口的调用者、个人会话与成果所有者、个人额度承担者均为当前用户。不得用智能体创建者替代实际调用者或授权主体。
- 私人内容默认隔离。管理员对配置、权限和用量的管理权不自动授予私人内容读取权；如实施私人内容访问能力，须独立授权并审计，本规格不因此要求新建内容审查产品。
- 任务所用资料、模型和工具均由应用按当前有效授权提供；模型输入、工具参数、项目引用和旧成果标识均不能扩大访问权限。
- 配置式智能体支持首版所需指令和模型配置。已启动执行使用初始化配置，持有旧配置不保留已撤销的权限。未来暂停恢复、子任务与外部入口的边界保留，但首版不实现这些流程。

### 3. 持久化与任务契约

- MySQL/InnoDB 保存身份授权、配置、会话消息、任务与幂等记录、成果版本与文件索引、模型调用和额度记录；持久文件目录保存原始资料、工作文件与正式成果内容。SDK 状态不替代业务权威。
- 提交请求校验身份、资源与模型权限，建立持久任务身份和同会话执行约束；接受请求不等于业务完成。页面观察与服务端执行分离，具体观察传输协议留到接口设计。
- 同一请求的并发或断连重试应返回同一任务，不重复执行；同一请求标识却改变参数不能悄悄当作同一输入。幂等记录按调用者及实际业务边界隔离。
- 同一会话同时最多一个任务，不实现同会话排队或并行分支。不同会话可在部署容量内并发。业务取消不等于资源已清理，新处理任务仍须满足管理服务的准入条件。
- 模型调用和文件处理在数据库短事务之外执行。业务状态、幂等、会话互斥及版本提交须由正式持久化机制保证，不能照搬原型的 JVM 锁和单文件替换作为生产一致性方案。
- 主进程重启后保留已保存内容，将遗留未完成任务记为中断；不自动续跑，不因重连或重提旧请求重新启动中断任务。

### 4. 取消、失败与成果提交

- 文字文档先在任务工作区准备，再由主应用提交为具有独立身份和版本的正式成果。用户在会话中继续修改，生成新版本，旧版本保持可读；文件格式与编辑交互尚未确定。
- 正式提交与取消在同一任务状态边界内协调，校验终态并登记版本。取消先成立时，迟到及重复成功响应不得发布；正式成果已经成功提交时，后到的取消不删除它或追溯改写完成事实。
- 保存失败不得改变旧成果版本或把不完整内容登记为成功。数据库与文件之间的提交、孤立临时文件清理及故障恢复需在实现中验证，不宣称两种存储天然具有统一事务。
- 失败、取消和中断保留已保存成果与已知用量；清理工作区不得删除原始资料和正式成果。首版不承诺回滚已经发生的模型执行或外部费用。
- 业务终态、处理进程状态和清理状态分别表达。无法确认停止时保留未知；只有核验实际资源已删除后才确认清理完成。原型的“允许保存”是测试故障控制点，不是产品人工审批步骤。

### 5. 受控处理与容器外期限

- 平台预置资料读取、解析/转换和文档生成工具；模型负责理解与组织内容，只能调用获准的业务工具，不开放任意 shell 或临时生成代码执行。
- 文件解析与转换显式交给任务容器。SDK 配置工作区或注册 Java 工具不会自动提供 OS 隔离；不允许在接入困难时默认改为宿主直接解析。
- 主应用不持有 Docker socket，通过内部控制网络向沙箱管理服务提交获准资料与固定操作；管理接口不发布宿主端口，实施服务身份验证与逐任务访问授权。
- 管理服务固定镜像、命令、宿主挂载、网络与资源限制；不接受任意执行参数或 Docker API 转发，不持有主数据库及模型凭据，不接管智能体循环或成果权威。每个处理容器仅获得本任务所需文件。
- 管理服务负责容器关联的持久记录、日常取消/超时终止、删除核验和启动定向回收。SDK stop、超时返回、调用取消或宿主客户端退出均不单独作为容器内进程已停止的证据。
- 独立执行看门狗使用 Docker 记录的容器创建时间和实例标签在处理容器外执行期限；处理程序不能自行延长期限。看门狗无网络、业务凭据或对外 HTTP 接口，恢复后继续使用原创建时间，不重置期限。
- 管理服务和看门狗分别持有完整 Docker daemon 权限，均为高权限信任边界；主应用和处理容器均不持有。这不等于 rootless、Docker API 权限裁剪或已证明可以抵御内核逃逸。
- 看门狗健康记录过期或清理未确认时，管理服务拒绝新增处理任务。清理失败持久保留待重试及未知状态；恢复后重试并确认删除，不能吞掉错误后报告成功。
- 主应用与管理服务失效后的停止上限，以看门狗、Docker 引擎、宿主调度和时钟可用为前提。整机、daemon 或监督整体不可用时不承诺墙钟上限，恢复后重新核对回收。生产期限及余量必须在目标环境验证；探针 15 秒阈值、15.235 秒样本不作为生产 SLA。

### 6. 模型用量与内部额度

- 每次模型调用有独立记录并关联任务、用户、可获得的 SDK/供应商标识、时间与用量来源；一项任务中的其他调用已有用量，不能掩盖当前调用的缺口。
- 供应商返回有效用量时按回报核算内部额度；缺少完整回报时按可观察输入输出估算并注明来源。执行收尾后释放预占，不因最终消耗未知而长期冻结。
- 已知用量在失败、取消或重启后保留；同一调用的重复累计回报不得重复扣减。内部估算和供应商实际用量分开记录，后者无完整依据时继续标注“用量待核实”。
- 本地订阅取消、HTTP 连接结束、供应商执行终止和供应商计费分别核实；未知不置零，不为拿到用量而默认让已取消任务继续生成。
- 预占金额、估算算法、无法可靠估算时的处理及后续差额调整仍需在计量设计中明确。本规格不承诺已完成逐请求对账，也不承诺内部预算与供应商费用绝无差额。

### 7. 部署与运营

- 单机 Docker Compose 部署主应用、MySQL、仅存登录态的 Redis、沙箱管理服务和执行看门狗，按任务创建受限处理容器；使用持久目录。不增加消息队列或 Kubernetes，不拆出完整智能体运行服务。
- 接受升级维护窗口及主进程故障导致运行任务中断。升级前备份，恢复时协调数据库记录与文件，验证已保存资源及版本可读。
- 任务、模型调用、工具执行、失败和清理记录应可关联定位；诊断记录不得泄露模型/数据库凭据，管理诊断入口仍服从私人内容权限。
- 目标服务器、正式模型资源、凭据分发、备份位置和恢复目标需在部署准备中落实，不默认复用其他项目资源。

## Testing Decisions

以下测试边界已于 2026-11-16 经用户确认：业务 API 为主，补充关键浏览器流程及真实 Compose/Docker 隔离与故障恢复测试，正式模型另做集成验收。

### 主要入口与两项必要补充

1. **主要测试入口：主应用面向 Web 的业务 API。** 以真实身份认证和授权为入口，覆盖提交、查询、取消、成果访问和额度结果，使用真实 MySQL 与持久文件验证状态一致性。常规自动化在模型供应商边界使用可控替身，不模拟掉被验收的授权、数据库或成果提交机制。
2. **浏览器补充：少量关键端到端流程。** 验证登录、直接提供资料、进度展示、成果预览下载，以及关闭页面后重新进入、隔天找回和继续修改。浏览器用于证明用户确实能完成工作，不把所有故障组合重复成 UI 测试。
3. **隔离与恢复补充：真实 Compose/Docker 和目标 Linux 环境。** 经管理服务实际接口触发任务，由测试环境注入进程退出、清理失败、通信中断和监督失效，并独立观察容器/子进程、业务记录与文件。纯 API 成功响应不能证明进程已停止，模拟 Docker 不能替代这组验收。

这是一条以业务 API 为主的测试入口，配合浏览器和运行环境验证；不为每个内部类、SQL 语句或 SDK 调用增加对应测试入口。对计量等确有必要的纯计算行为可做小型测试，但最终仍通过业务可见结果验证。

### 验收矩阵

| 编号 | 必须证明的行为 | 入口与证据 |
| --- | --- | --- |
| T01 | 管理员配置账号、模型权限与个人额度；普通用户仅能使用获授权配置，管理角色不自动读取私人内容 | 业务 API＋关键管理/登录页面；正式认证与跨用户反向用例 |
| T02 | 独立会话、项目组织和移入移出正常；删除项目保留会话及成果；关联不改变所有权 | API 查询资源身份、归属、内容及版本；浏览器覆盖代表工作流 |
| T03 | 直接提供资料，选择获授权模型或配置式智能体，生成可预览下载的文字文档 | API＋浏览器；真实格式样本、实际工具路径及可读的正式输出 |
| T04 | 隔天找回，基于旧成果继续修改形成新版本，旧版内容不变 | 持久化及浏览器验收；重启前后读取、预览和下载均一致 |
| T05 | 跨用户查看、取消、引用、下载及资料路径越界被拒，不能从模型输入扩大授权 | API＋真实处理环境；至少两个独立用户/任务的正反向对照 |
| T06 | 并发重复请求只建一次任务；同键不同参数拒绝；同会话互斥，不同会话在容量内可运行 | 并发 API 请求及持久任务、成果、调用记录；不能只测内存锁 |
| T07 | 断开提交/观察连接后后台继续，重新查询仍为同一任务，不重跑或重复计量 | 独立连接的 API 请求＋浏览器关闭重开 |
| T08 | 发布前取消拒绝迟到及重复结果；发布已成功后取消保留完成事实；保存失败保留旧版 | 可控模型/故障时点，经实际业务提交路径竞争；核对数据库登记和文件完整性 |
| T09 | 主应用强杀重启后未完成任务为中断，不自动续跑；旧成果、已知用量与幂等关系保留 | 真实进程重启与同一持久存储，再经 API 查询和下载 |
| T10 | 成功、失败、取消及调用用量缺失时，已知回报保留、缺失逐调用估算、预占释放、未知不置零；重复回报不重复扣减 | 可控模型响应＋实际额度持久化；真实供应商小规模集成另验 |
| T11 | 平台工具确实在受限容器处理，只获得获准文件，凭据不可见，网络/挂载/资源限制生效 | 真实 Compose/Docker；同时验证非法管理参数、错误服务身份和跨任务访问被拒 |
| T12 | 管理服务重启回收仍有心跳的遗留任务，且不误删其他实例资源 | 故障前证明容器/子进程存活，故障后独立核验实际停止、删除及查询状态 |
| T13 | 删除拒绝和管理服务到 Docker 通信失败持久记录待重试与未知，拒绝新增，恢复后确认回收 | 实际管理接口＋受控故障注入；不能用无条件 mock 成功替代 |
| T14 | 主应用与管理服务同时失效后，独立看门狗按创建时间终止逾期处理；伪造期限无效；监督失效拒绝新任务 | 真实容器/子进程观察和时间记录，含不同实例对照；按目标机经验证的期限与余量验收 |
| T15 | 正式模型能完成资料理解、正文生成和工具调用；取消传播与用量缺口如实记录 | 经授权的真实模型、受控资料和预算；不把本地取消视为供应商停止或结清 |
| T16 | 实际部署、升级和一次协调的备份恢复后，用户内容、版本及对应索引一致，故障可定位 | 目标 Linux 及恢复环境；数据库和文件共同恢复，已保存内容可实际读取 |

### 原型先例与上线门槛

- 运行闭环探针已有 HTTP 提交/查询/取消、断连、并发重提、用户隔离、实际发布及强杀重启测试，可复用行为案例与故障时点设计；模拟身份和单文件原子替换不直接成为生产方案。
- 沙箱第三阶段已有真实 Docker、活遗留容器回收、跨服务迟到成功响应、清理失败重试、独立看门狗期限与对照容器证据，可复用验证思路；固定合成转换程序不证明真实解析器安全或兼容。
- 常规回归使用合成资料与模型替身，正式模型和真实工作资料在独立的授权验收中验证；模型文本不以逐字相等作为普遍通过条件，应检查任务要求、内容可读性、工具实际执行与成果版本。
- 上线前必须由产品发起者及试用同事用真实资料独立完成“生成方案 → 隔天找回 → 继续修改”的闭环，并通过权限/额度、任务可见行为、重启中断与内容保留、部署升级及备份恢复门槛。
- 当前仅定义测试计划，不将任何 T01–T16 标记为正式产品已通过。精确性能数字和生产停止期限需先明确测试环境及负载，再记录结果；全宿主/监督整体失效时的无条件墙钟上限不属于承诺。

## Out of Scope

- 公开注册、多实例高可用、自动扩容、无维护窗口升级、任务崩溃后自动续跑、精确重放、同会话排队或并行分支。
- 钉钉登录、DWS、其他外部业务系统与企业登录集成的完整覆盖；首版具体登录方案另行细化，不默认纳入完整产品愿景中的所有方式。
- 用户上传可执行 Skill、MCP 接入、任意 shell 或临时生成代码执行、插件体系、多智能体协作及通用人工批准工具流程。
- 内部市场及发布审批、直接分享、会话快照分享、成果对外分享；相关资源归属与未来复制/授权规则仍须保持兼容。
- IM 机器人、智能体对外服务、对外模型网关和接入应用管理；不建设通用外部智能体程序托管平台。
- 个人长期记忆、平台知识库、联网搜索等未被首版决议纳入的完整聊天产品能力；直接提供当前工作资料仍在范围内。
- 桌面端、移动端、视频创作、生图、语音输入，及表格、演示文稿、交互网页等成果类型。
- 完整供应商账单对账、取消后上游零消耗保证、全宿主故障下的无条件停止 SLA、已验证抵御内核逃逸的承诺。
- 本轮只形成实施规格；不在此批量拆建开发票、编写业务实现或执行生产部署。

## #11 身份与会话落地边界 · 2026-11-16

本条取代前文“不增加 Redis”及登录方式待定的描述。采用用户名密码登录，无公开注册；初始管理员由外部秘密配置初始化，首次改密。管理员仅创建普通用户并启停/重置，不能编辑角色或禁用初始管理员。密码恢复走部署命令。Redis Session 的闲置 7 天与绝对 30 天限制独立，密码/状态变更原子递增 MySQL authVersion，每次受保护请求检查即时身份。Redis 仅存登录态，不保存业务记录。

#11 只实现会话新建、分页列表与空详情（默认“新会话”），查询始终按个人 owner 限定，管理身份无私人内容读取特权。本节不代表消息、项目空间、模型、后台任务或资料处理已交付。接口、错误和验证合同见 [#11 实施合同](issue-11-design.md)。
