## 自动化验证

- API 红绿：新增 DOCUMENT 请求先返回 400；实现后资料解析→生成工具→正式登记→下载全文核对通过。成果、版本、任务 ID 独立，正文为约定 UTF-8 Markdown。
- 同轮重复生成工具和重复请求仅登记一份版本；同 requestId 改输出模式返回 409。TEXT 默认保持旧请求指纹兼容。
- 模型不提供文档正文时任务失败；正文准备后、发布前取消，不登记成果。正式提交后再取消保留完成态和原版本。
- 真实文件故障：暂把正式目录替换为普通文件，发布失败且旧版在恢复后原样可读。真实 DB 故障：暂把版本表移名，版本 INSERT 失败后整个成果登记事务回滚，恢复后列表无假成果，旧版仍可读。最初触发器注入因普通数据库用户缺 SUPER 权限被拒，改用测试库内可恢复的表不可用故障，没有扩大正式账号权限。
- 修改正式文件内容后下载返回 503，恢复原字节后可读；所有权校验覆盖列表、预览和下载。原始资料不因工作区清理或新成果保存改变。
- 完整 `-Pdistribution clean verify`：21 项测试，0 失败、错误、跳过（包含真实隔离服务的 MaterialParsingTest）。前端 19 项、类型检查、构建通过；后续仅修正原生表单 reset 并再次通过前端检查与打包。
- 两轴代码审阅未发现阻塞项。未使用内部服务 mock 替代发布/取消/文件保存行为。
