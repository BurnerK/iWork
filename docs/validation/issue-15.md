# #15 资料输入验收

环境：隔离 Compose 项目 `iwork-issue12-check`，MySQL 8.4.7 / Redis 8.2.3；本地服务 18092，合成管理员、合成模型配置及仅测试 classpath 的任务替身。没有真实供应商调用。

- API：原始字节上传、中文文件名下载、所有权隔离、他人资料引用拒绝、同名不覆盖、非法路径/扩展名、空文件/超限拒绝、损坏原文拒绝下载；失败输入不进入可引用列表。
- 任务：资料引用与任务同事务保存，变化的资料集合不能重用原幂等键；无资料旧请求保持兼容。
- 后端：`-Pdistribution clean verify` 19 项通过，包含新时间断言；正式 JAR 重启后原文仍可读，旧资料 createdAt 修正为实际上传时刻 `2026-11-16T17:42:40.571586Z`。
- 前端：15 项通过；包括真实 File 请求体、资料选择、刷新后不确定任务重试，以及审查发现的上传/提交竞态回归。
- 浏览器：上传 `验收资料.txt`（89 字节），刷新页面后列表仍存在，重新选择并提交；任务 `8352b260-3fb0-4ecf-abaf-ffa56296ccf0` 的资料查询返回 `85642913-9969-4723-88b5-74e1026c395c`。浏览器下载文件与原文 `cmp` 完全相同。390px 视口无横向溢出，文件输入可获得键盘焦点。
- 两路代码审查：均指出上传尚未结束时任务可漏带资料；已同步上传状态到父级并复核通过。无剩余规范或规格问题。
- 验收发现共享 JDBC 时区假设导致时间偏移 8 小时；新增上传时间区间断言先失败，连接和数据库会话统一 UTC 后重测。依据 [Connector/J 日期时间属性](https://dev.mysql.com/doc/connector-j/en/connector-j-connp-props-datetime-types-processing.html)。数据库默认时间生成的 created_at 不需要重写。审查指出旧配置下 Java 写入的 `users.locked_until` 可能已经偏移：升级前必须核查非空锁定时间，不能直接把时间修正当作无数据影响变更；#25 部署验收需覆盖该升级边界。当前尚未部署到外部实例。
