# #25 阿里云 ECS 单人验收记录

2026-11-20，中国标准时间。广州 ECS，Alibaba Cloud Linux 4 LTS，2 vCPU、2 GiB 内存、40 GiB ESSD Entry，Docker 24.0.9、Compose 5.5.1。iWork 通过 SSH 隧道访问，应用端口绑定宿主回环。服务器有 zram，原站与恢复副本应用分时运行。按单个任务、单个解析容器验证。

## 升级

- 09:45:32 至 09:45:46 将 ECS 原实例从 `01ed18d` 升至 `5447663`。应用镜像摘要（本地镜像 ID）为 `sha256:4642042e9008329279d9e59dca3d2d15ab57d18067b20bc1907da6e23a2c8bd1`。
- 维护开始时无其他运行任务。发起一个合成模型任务，确认处于 `RUNNING` 后强杀应用，在停止业务写入后备份。升级后该任务变为 `INTERRUPTED`，未自动执行。同一个请求 ID 再提交仍指向原任务，用量记录没有增加。
- 重新登录、查到已有任务和成果版本，下载原文与成果并比对 SHA-256，一致。
- 第一次演练遇到云盘 I/O 等待及数据库超时，在换镜像前停下并恢复旧版。随后明确指定应用实际使用的业务库，并将逐表计数合并为一次 MySQL 调用，重跑备份和升级通过。

## 协调恢复

- 源备份包含 MySQL 业务库与文件，总计 22 张表、2 个文件引用。备份与恢复工具分别核对数据库表行数以及文件大小和 SHA-256。
- 备份目录和文件权限分别为 0700 和 0600。源与副本各用专属数据库，文件目录独立。备份及副本数据保留在 ECS。
- 恢复到同一 ECS 上的独立 Compose 项目。副本使用新 MySQL、Redis、文件目录和凭据。恢复校验通过后，用原有管理员重新登录，通过业务 API 找回任务、调用用量、正式版本、原文和成果下载。
- 用受控模型在恢复的原会话显式发起新任务，诊断为 `RESTORED`，旧成果字节不变。另建普通用户，读取他人的任务、资料和成果被拒绝，管理员模型入口也被拒绝。原实例中的源任务使用真实模型。

## 沙箱与看门狗

- 管理器和看门狗无宿主发布端口，无模型或数据库密码。看门狗使用无网络模式，管理器只读挂载其心跳。
- 真实容器解析 2 MiB 文本成功并确认移除，超出 1 字节被拒绝，错误服务密钥及任务令牌被拒绝。看门狗失去新鲜心跳时，管理器拒绝新增解析。
- 管理器重启移除本实例遗留容器。带其他实例标签的对照容器未被移除。
- 强杀副本应用与管理器后，独立看门狗在容器创建后 60.637 秒确认移除。从标记过期到确认删除用时 199 毫秒，总计超出 60 秒租期 637 毫秒。这是当次单容器测量。扫描间隔为 500 毫秒，实际余量还取决于 Docker 响应速度、主机调度和时钟。
- 在副本管理器一侧注入删除拒绝和 Docker 客户端通信失败。真实工作容器仍在，清理状态持久化为 `UNKNOWN`，拒绝新增任务。管理器重启后仍保留该状态。解除故障后重试成功，Docker 确认容器消失，清理状态改为 `CONFIRMED`。

## 演练结束

原站 09:50:28 恢复可用。通过隧道重新验登录、任务和文件，并用真实 DeepSeek 跑完一条文本任务，耗时 3.89 秒，记录到供应商用量。复查空闲可用内存约 443 MiB，系统盘剩余约 26 GiB。原站保留文本模式，解析服务仍停用。恢复副本已停，故障注入已退出运行配置。宿主 80/443 未监听。

## 单人使用的权限与预算复验

- 普通测试账号无权给自己授权模型或修改预算，也无法读取其他用户的会话、调用用量、原文和成果。授予单个模型权限后模型可用。撤销权限后，新任务被拦截且没有新增调用或扣账。
- 日常 DeepSeek 模型在 iWork 的输入和输出单价均为零。改用独立计价测试配置，零额度和仅剩 CNY 0.000001 的场景均得到 `budget_exhausted`，没有模型调用、扣账或预算占用。额度充足后真实模型完成，记录到供应商用量，按测试单价计入 CNY 0.000229，占用归零。
- 测试账号和计价测试模型已停用，测试账号授权已撤回。

本轮通过 SSH 隧道使用业务 API 验证，仍待用户页面验收。实测覆盖强杀应用和管理器、清理故障，以及单任务低并发条件。未演练存储断联、断电、全宿主失效、跨机器恢复、持续并发或完整 T17–T19 矩阵。生产 HTTPS 与异地备份也未验收。
